## What was built

- **Effects.** A fixed point over the lowered module: traps from check instructions, `trap`, unreachable terminators and trapping intrinsics (including release functions), allocations from the allocating intrinsics, spawns, unsafe from `unsafe` blocks and unsafe intrinsics; calls through function values make every effect possible with label `unknown`, calls into FFI with `assumed-unsafe`, destructors are followed through the type's glue.
- **Structured edits.** Rename resolution against the unedited files for locals, parameters, bindings, functions and types (uses through resolved identifiers and type names), expansion into replacements attributed to the rename's index, conflict and coordinate validation reporting the failing op of lowest index, replacement/insert ordering per §16 (4), the `formatted` flag from a formatter round trip, and the diagnostics of a check on the edited sources.
- **Incremental checking.** Interface files serialize exported types with layout and derived markers, generic bodies as source text, constants, thread-locals, function signatures with conventions and contract blocks, and a syntactic effect summary per function; the interface hash also records whether the module had diagnostics, because a full check does not report dependents of a module that failed to resolve. Entries are written per module in dependency order so dependents hit on the next run; a full hit returns the sorted union of the entries. The CLI exposes it as `kern check --cache=DIR [--opt=…] [--env=…] [--target=…]`.
- **Agent harness.** Provider-neutral conversations with tool definitions, OpenAI chat-completions and Anthropic messages clients (retrying on rate limits), per-trial recording of every tool call, hidden tests after each iteration for regression counting, unsafe lines added by diffing `unsafe` spans, budget scoring, and a `-dry-run` that validates every task's reference solution and confirms the starting sources fail the hidden suite.
- **Language fixes found by the work.** Imported constants are resolvable through module paths (`tests/positive/import_const/`); the `[unproven]` codegen comparison and the checks-elided measurement are harness experiments only.

## Deviations from the plan

- **The agent matrix is not run.** Ten tasks × two models × two arms × five trials is up to 200 agent runs of up to 30 minutes and 20 iterations each, against paid APIs. The harness, tasks, hidden suites and aggregation rule are complete and validated (`-dry-run` passes for all ten tasks; a one-trial pilot of the debugging task per arm with `openai:gpt-6.1-sol` succeeded in both arms in 5 iterations, `bench/agent/REPORT.md`), and the run is a cost decision for the project owner: `go run ./bench/agent/harness` executes it and regenerates `bench/agent/REPORT.md`; the paragraph in `docs/research-report.md` §4 is then replaced with its result.
- **The OpenAI client uses the Responses API** (function tools with this provider's reasoning models are not available on chat completions); the conversation is resent statelessly each step. Both arms use the same client, so the ablation stays controlled.
- **Rename coverage.** `rename_symbol` resolves locals, parameters, bindings, functions and struct/union types; fields and methods are not renamed (they resolve through field expressions, which the rename does not yet follow).
- **Effects for imported modules in interface files are syntactic** (an over-approximation used only for cache invalidation); `show-effects` itself is exact over the lowered program.

## Reviews

- **prism** (OpenAI gpt-6.1-sol, staged diff, docs/fixtures/benchmark programs excluded): 22 findings (4 high, 18 medium); 20 addressed: the effects analysis propagates to a fixed point over recursion; interface files resolve declaration files by node identity and make any call carry every effect (a conservative key); requests with resolution errors are not cached; cache entries are written through unique temporary files; rename failures take part in the lowest-index selection, declaration names are matched as whole identifiers, and qualified references to an imported type are renamed in every module; the agent harness applies the trial deadline to tools and hidden tests, fails dry-run on an invalid task, aborts on workspace or record-write failures, counts regressions as passing-to-failing transitions, distinguishes checker failures from clean checks, fails closed on malformed analysis output, and bounds every HTTP request; the benchmark report uses the Rust release row for the aliasing context and reports tag cost as execution-time overhead; the citation lint checks every prose paragraph. Two findings are recorded as design limits instead: thread-local initializers are serialized as their constant values (deterministic for the literal kinds the language permits), and a single cache miss re-runs the whole program (resolution is whole-program; the plan requires identical diagnostics, which the key design guarantees, not partial reuse).
- **realitycheck** (spec + plan, OpenAI gpt-6.1-sol, `--max-tokens 65536`): PARTIALLY_ALIGNED, score 100, no drift, no violations (the usual inventory-only PARTIAL/UNCLEAR items; Phase 5 unimplemented as expected).
- **verifier** (offline): 98 low-severity unit gaps; the incremental cache, structured edits and citation lint have their own tests, the effects analysis is covered through the command test.

## Known limitations carried into Phase 5

- The incremental cache has no eviction; entries accumulate per key.
- The agent harness measures the interpreter (`kern run`) for hidden tests; native builds are not part of the tasks.
