# Standard library: borrowed map lookups, map visits, formatting, UTF-8

**Date:** 2026-10-30. **Spec:** `specs/std-gaps/SPEC.md`. **Plan:**
`specs/std-gaps/PLAN.md`. **Closes:** four of the gaps listed under
"Not done" in `docs/reports/std-library.md`.

## What was added

All of it is safe kern in the two embedded modules
(`compiler/resolve/prelude/map.kern` and `str.kern`, mirrored under
`std/`). No compiler change was needed.

**`std/map`:**

- `find(view self, key: view[K]) -> Option[usize]` is a lookup that
  borrows its key and returns the entry's slot. A `String` key stays the
  caller's.
- `key_at(slot)`, `value_at(slot)` and `value_at_mut(slot)` view or edit
  the entry in a slot. A slot past the table traps `bounds`; an empty
  slot traps `explicit`. A slot stays valid until the next `insert` or
  `remove`, since `insert` may rebuild the table.
- `find_text(m, bytes)` looks up a `String`-keyed map by a byte view
  without building a `String`, using the hash and equality `String`'s
  `Hashable` uses.
- `each(f)` and `each_mut(f)` call a closure with every entry: key and
  value views, or a key view and a value edit. They go in slot order,
  which is the same for two maps built by the same inserts and removals.

**`std/str`:**

- `String` gains `push_i64` (the minimum `i64` included), `push_hex`
  (lowercase, no prefix) and `push_padded(v, width, fill)`.
- `push_rune(code)` appends a scalar value's UTF-8 encoding. It refuses
  a surrogate or a value above U+10FFFF and appends nothing.
- `Rune { code, len }` and `utf8_decode(s, at)` decode one scalar value.
  The decoder follows Unicode's Table 3-7, so overlong forms,
  surrogates and values above U+10FFFF are rejected by the second
  byte's range.
- `utf8_valid(s)` and `utf8_count(s)` validate and count.

## Why the map API has this shape

- **Lookups return a slot, not a view.** A function with two access
  parameters cannot return an access (the elision rule, §5.3), so
  `get(view self, key: view[K]) -> view[V]` cannot be written. `find`
  returns a slot, and the accessors, which have one access parameter,
  turn it into a view or an edit.
- **A borrowed key needs a place.** `find`'s key is a view, so a literal
  has to be bound first (`k := 7u64; m.find(k)`). The existing
  `contains`, `get` and `at` keep taking the key by value for literals
  and temporaries.
- **Visiting is by closure.** Closures capture by access for the
  duration of a call and cannot be stored, so a visiting method that
  takes a closure is the iteration that fits. A closure that reaches the
  map being visited conflicts with the visit's own access to it, and is
  rejected with `ACC_CONFLICT`, so a map cannot change under its own
  visit.
- **Projections are bound with `with`.** An edit through a slot is
  written `with v := m.value_at_mut(s) { v = 333u64 }`. Assigning to the
  projection directly takes the map twice and is rejected, as it is for
  `Vec.at`.

## Verification

Every fixture runs in the interpreter and natively, in debug and
release.

- **`tests/run/std_map_borrow`** covers:
  - `find` on present and absent keys, with the owned `String` key
    printed afterwards;
  - `find_text` on present and absent byte keys, and the same slot as
    `find` for the same key;
  - the slot accessors, including an edit;
  - `each` summing, `each_mut` updating, and `each` printing every
    entry;
  - the same visit order for two maps built alike;
  - no visit on an empty map.
- **`tests/trap/map_value_at_vacant`** traps `explicit`, and
  **`map_value_at_past`** traps `bounds`.
- **`tests/negative/map_each_conflict`** (a closure that reaches the map
  given to `each_mut`) and **`user_each_conflict`** (the same shape
  through a user function) both give `ACC_CONFLICT`. Each has an
  accepted twin.
- **`tests/run/std_str_format`** and **`std_utf8`** cover the formatting
  boundaries, every boundary scalar value encoded and decoded back, and
  each malformed form. Their expected outputs were generated by a
  separate Go program using `strconv` and `unicode/utf8`, not written
  from the kern code.
- **`tests/utf8_diff_test.go`** checks `utf8_valid` and `utf8_count`
  against Go's `utf8.Valid` and `utf8.RuneCount` on 600 strings from a
  fixed seed. Two thirds are near-valid chunks: every lead byte followed
  by one fewer, as many or one more continuation bytes, drawn from the
  whole continuation range. A third are well-formed strings of random
  and boundary scalar values.

  Checked by mutation, the test catches four widened ranges, each with 1
  or 2 mismatching strings: surrogates accepted, overlong 3-byte forms
  accepted, values above U+10FFFF accepted, and C0/C1 leads accepted.
  My first generator, built from loose bytes, caught none of them.
