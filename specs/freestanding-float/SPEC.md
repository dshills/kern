# Floating-point text on bare metal

**Version:** 0.4 (2026-11-04). **Scope:** the freestanding runtime
(`runtime/freestanding/src/`: a new `f64text.c` beside `rt.c`, embedded
by `runtime/freestanding/freestanding.go` and compiled as its own object
by `compiler/backend/native/build.go`); the interpreter's float parse
(`compiler/interp/clock.go`, R9); a host-side differential test; two
fixtures; documents. **Language impact:** none: no syntax,
type rule, diagnostic code or library signature changes.
**Review status.** speccritic (gpt-6.1-sol) round 1: saturating the
textual exponent at ±100000 broke texts whose digit run cancels it (now
10^18, with the bound argued in §2); the libc reference's locale and
rounding mode are stated; §2 is informative. Round 2: the cancellation
text's value (0.111…), and the stack bound covers the whole call chain.
Round 4: R3 no longer names headers. v0.4: `f64text.c` is its own lazily
linked object, since linking it into every image grew `hello` by 6 KB
(R7). Round 3: no undefined symbol at all (so no memory routine's stack to
count), and R9's rewrite is informative.
v0.3: the differential test found two `strconv` defects, so the
interpreter's parse is fixed too (R9).
**Related:** `specs/float-text/SPEC.md` (the two runtime entries and their
contracts; its non-goal "a freestanding implementation" is the one this
spec removes); `specs/freestanding-availability/SPEC.md` (Rule 6.8 and its
inventory); ADR-011 (the freestanding runtime).

**Glossary.** R*n*: requirement *n* of §3. ADR: architecture decision
record (`docs/adr/`). JSON: JavaScript Object Notation (RFC 8259 §6
gives the number grammar). libc: the host's C library. QEMU: the machine
emulator the harness boots images in. NaN and Inf: not-a-number and
infinity. The two entries:
`kern_str_f64_digits(double v, char *buf, int64_t n) -> int64_t` and
`kern_str_parse_f64(const char *p, int64_t n, const kern_loc *at) -> double`.
The hosted runtime: `runtime/hosted/src/kern_rt.c`, which implements the
entries with libc's `snprintf("%.*e")` and `strtod`. The reference: those
libc calls, and Go's `strconv.FormatFloat(v, 'e', p-1, 64)` and
`strconv.ParseFloat(s, 64)`, which the interpreter uses. The libc
calls run as the hosted runtime runs them: the C locale (the runtime and
the test driver never call `setlocale`) and the round-to-nearest mode
(neither calls `fesetround`). Correctly rounded:
the nearest value, ties to even. Round-trip digits: as defined in
`specs/float-text` (the smallest *p* in 1..17 whose correctly rounded
*p*-digit string reads back as *v*).

## 0. Goal and non-goals

A freestanding program must be able to format and parse `f64` text
(`String.push_f64`, `str.parse_f64`, `json.as_f64`, `json.number_f64`)
and gets the same bytes and values as a hosted build and the interpreter.
Today those calls are rejected with `ENV_HOSTED_ONLY`, because the
freestanding runtime defines neither entry.

Non-goals: changing the hosted runtime's implementation; a faster
algorithm (Ryū, Eisel-Lemire); `f32` text; a precision argument.

## 1. Background

The freestanding runtime is compiled with `-ffreestanding -nostdlib
-fno-builtin` and has no libc: no `snprintf`, no `strtod`, no `malloc`.
Its stack is 64 KiB (`start_*.S`). Its C source is `rt.c`, and `freestanding.Provided()` reads the external
definitions of the runtime's C sources to decide which runtime entries a
freestanding image has (Rule 6.8).

## 2. Design (informative)

This section describes the intended implementation; it is not normative.
§3 is: any implementation meeting R1 to R9 within R3's dependency and
stack limits is acceptable.

Both entries are computed exactly with fixed-size unsigned big integers
(32-bit limbs) on the stack, with no allocation.

**Formatting with *p* digits.** For finite nonzero *v* = *m*·2^*e*, the
exact value is the ratio *num*/*den* of two big integers. The decimal
exponent *E* with 10^*E* ≤ |*v*| < 10^(*E*+1) is estimated from the binary
exponent and corrected by one comparison step each way. Digits are
generated by repeated multiply-by-10 and quotient (each quotient digit
is 0..9 and found by subtraction); after *p* digits the remainder decides
rounding: up when 2·*rem* > *den*, or when 2·*rem* = *den* and the last
digit is odd. A carry out of all nines gives `1` followed by zeros and
*E* + 1. Zero formats as `0e+00` (`-0e+00` for −0).

**Round-trip digits.** For *p* = 1..17, format with *p* digits, parse the
result with the parser below, and stop at the first *p* whose value has
the same bits as *v*. This is the hosted runtime's search with exact
arithmetic in place of libc.

**Parsing.** The input is one JSON number (the caller has checked it).
Leading zeros of the significand are skipped; at most 800 significant
digits are kept, and when any dropped digit is nonzero, an 801st digit
`1` is appended (a sticky digit). A halfway point between two adjacent
doubles has at most 767 significant digits, so the kept digits round the
same way as the full text. The exponent's digits saturate at 10^18: the
digit counts that adjust the exponent (dropped integer digits, fraction
digits) are below the text's length, so for any text shorter than
10^17 bytes a saturated exponent is still far beyond ±400 after
adjustment, and the value is ±Inf or ±0 exactly as for the true one. With *N*
the kept digits and *E* the adjusted exponent, a value whose leading digit
is at decimal exponent above 309 is ±Inf and one below −324 is ±0, with
the text's sign; otherwise the ratio *N*·10^*E* is scaled so the quotient
has 53 significant bits (fewer for a subnormal, whose scale is fixed at
2^1074), the quotient is found by shift-and-subtract long division, and
the remainder rounds it to nearest, ties to even. A carry to 2^53 moves
the exponent up by one; an exponent past the largest finite one is ±Inf.

Big-integer sizes: the largest intermediate is below 2^4300 (801 digits
times 10^1125 scaled by at most 2^1130, and *den*·2^54), so 160 limbs of
32 bits (5120 bits) suffice; each entry uses at most six such values on
the stack (under 4 KiB).

## 3. Requirements and acceptance criteria

Each requirement is an acceptance criterion; R5 and R6 are the tests that
check R1, R2 and R4, and R3's checks are part of R5's test.

**R1. Byte equality of `kern_str_f64_digits`.** For every finite `f64`
*v* and every *n* ≥ 0, the freestanding entry writes the same bytes and
returns the same length as the hosted runtime's entry, which equal
`strconv.FormatFloat(v, 'e', p-1, 64)` for the round-trip *p*, with the
exponent written with at least two digits. *n* < 0 is treated as 0, and
output longer than *n* is truncated to *n* bytes, as in the hosted entry.

**R2. Value equality of `kern_str_parse_f64`.** For every text that is one
JSON number, of any length, the freestanding entry returns a double with
the same bits as `strtod` of that text and as the interpreter's
`str_parse_f64` (R9). It equals `strconv.ParseFloat` too (±Inf where that
reports a range error, ±0 where it underflows) except on texts where
`strconv` itself is wrong, which the test pins with their correctly
rounded values: an exponent whose digits `strconv` stops reading near
10000 before adding the digit position (`0.` 100,001 zeros `1e100002`),
and an integer part over 800 digits that `strconv`'s slow path places 10
times too small per extra digit. It never allocates, never traps and ignores `at`; text with
*n* ≤ 0 is never passed (the caller's JSON check requires a digit).

**R3. No new runtime dependency.** `f64text.c` includes no header but
the compiler's own freestanding ones, defines no external symbol other than the two entries (every
helper is `static`), and calls no function outside itself; the runtime
still compiles for both freestanding targets with the existing flags, and
`llvm-nm` of the object compiled alone (with the runtime's flags) lists
no undefined symbol at all, so an entry calls nothing outside the file
(not even a compiler-generated memory routine). Each entry's whole call chain uses
under 8 KiB of stack: the test checks that the sum of every function's
frame in `f64text.c` (from `-fstack-usage`, all static) is under 8 KiB,
which bounds every chain because nothing in the file recurses.

**R4. Availability follows.** `freestanding.Provided()` includes both
entries, so `ENV_HOSTED_ONLY` no longer fires for the four float
functions; the generated inventory in
`docs/reports/freestanding-availability.md` is regenerated and no longer
lists them (other hosted-only functions are unchanged).

**R5. Differential test.** A Go test (skipped when `clang` is absent)
compiles `f64text.c` with a C driver for the host, and checks R1 and R2
three ways (freestanding entry, the libc calls the hosted entry makes,
and `strconv`), with the driver in the C locale and round-to-nearest
mode, on:
- every special case listed in §4;
- at least 100,000 random bit patterns (finite ones) for R1, and for R2
  their formatted texts at every *p* from 1 to 17;
- at least 100,000 random JSON numbers for R2: random significands of
  1 to 30 digits with random fraction and exponent parts, plus the exact
  decimal expansions of random halfway points with one added digit above
  and below;
- texts longer than 800 significant digits, including a halfway point
  followed by many zeros then a final nonzero digit;
- texts whose exponent cancels a long digit run: `0.` then 100,001 zeros
  then `1e100002` (exactly 1), and 100,001 digits `1` followed by
  `e-100001` (0.111…, which rounds to 1/9).
The seed is fixed; a flag raises the counts.

**R6. End to end.** A fixture `tests/freestanding/float_text.kern` (with
`.out`) formats and parses floats covering each layout branch of
`push_f64`, a subnormal, the largest finite value, `parse_f64` of a
rejected text and of an overflowing one, and `json.as_f64`; the harness
runs it in the interpreter and, where `ld.lld` and QEMU are installed,
natively on both freestanding targets, and the transcripts are identical.
`tests/freestanding/hosted_only.kern` is unaffected (it uses `time.now`).

**R7. Other images unchanged.** Hosted images and the hosted runtime are
not changed, and `rt.c` is not changed. `f64text.c` is compiled as its
own object and linked lazily (`ld.lld --start-lib … --end-lib`, or as an
archive member when the build writes an archive), so a freestanding
image that calls neither entry is byte-identical to the image the
previous compiler built: checked for every fixture in
`tests/freestanding` on both targets.

**R8. Documents.** The "Hosted only." notes on the four functions in
`compiler/resolve/prelude/str.kern`, `std/str.kern` and the JSON sources
are removed; `docs/reports/freestanding-availability.md` drops the
"Floats are hosted" finding; ADR-011 and `specs/float-text` get a note
pointing here; a report `docs/reports/freestanding-float.md` records the
test counts and the image size change of a freestanding fixture.

**R9. The interpreter agrees.** The interpreter's `str_parse_f64`
returns the correctly rounded value on every JSON number, including the
texts R2 names where `strconv.ParseFloat` alone is wrong. A test pins
those texts with their values and checks 50,000 random JSON numbers
against `strconv` directly (where it is right). The intended fix, which
is informative: rewrite the text before `strconv.ParseFloat` as its
significant digits (at most 800, then a sticky `1`) in `d.ddd` form with
the exponent of the first digit, or as `1e400` or `0` with the sign when
the leading digit is above 10^309 or below 10^−324.

## 4. Special cases (R5)

±0, ±the smallest subnormal (2^−1074), the largest subnormal, the
smallest normal, the largest finite value, 1, 0.1, 0.3, 2^−24 (whose
round-trip digits are 17, see `specs/float-text`), 5e-324, 1e23 and
9007199254740993 (a halfway point in text), every power of ten from
10^−323 to 10^308, every power of two from 2^−1074 to 2^1023, and these
texts for R2: `0`, `-0`, `0.0e0`, `1e400` (+Inf), `-1e400` (−Inf),
`1e-400` (0), `2.4703282292062327e-324` (rounds to 0, below half the
smallest subnormal), `2.4703282292062328e-324` (rounds up to the smallest
subnormal), `1.7976931348623158e308` (largest finite),
`1.7976931348623159e308` (+Inf), and an exponent of 99999999999.

## 5. Failure modes

A wrong digit or rounding fails R1/R2 in the differential test with the
input printed. A stack overflow in a native image traps `stack` (the
compiler-inserted check covers only kern functions, so the C entries must
stay under R3's stack bound).
